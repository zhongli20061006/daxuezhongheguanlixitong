# 智伴校园统一系统提示词设计

日期：2026-08-03
状态：已批准（讨论确认）

## 背景与问题

智能体（首页对话窗口）目前有三条 LLM 调用路径，提示词维护零散：

1. **意图识别**：`intent.py` 中一份独立 `EXTRACT_SYSTEM_PROMPT`；
2. **聊天**：`_handle_chat` **完全没有系统提示词**，只注入事实记忆与历史；
3. **学习方案**：`_generate_plan` 里一句临时"只输出 JSON"。

由此产生的两类反复踩坑：

- **模型编造执行结果**：聊天路径无身份/边界约束，模型会答"已经为您提交了请假申请"之类的话，实际上什么都没发生；
- **按功能零散打补丁**：日期短格式、课程简称、意图误判等每次都单独修，费时费力且彼此不联动。

## 核心决策（已与用户逐项确认）

| 决策点 | 结论 |
|--------|------|
| 提示词与代码的分工 | **提示词管行为，代码管确定性**：身份/边界/格式/示例交给提示词；日期解析、课程模糊匹配、确认令牌、多轮续跑、规则兜底全部留在代码 |
| 覆盖范围 | 三条路径**一次全接**（意图识别 / 聊天 / 学习方案），采用"基础提示词 + 任务层"结构 |
| 示例策略 | **铁律 + 每任务 1~2 个 few-shot 示例**（小模型跟示例走） |
| 存放位置 | **代码常量模块** `app/services/agent/prompts.py`，随代码版本管理、可单测 |

## 架构与文件结构

新增 `app/services/agent/prompts.py`（纯常量模块，无任何依赖，不引入循环导入）：

```
BASE_SYSTEM_PROMPT        # 身份 + 5 条铁律（唯一权威来源）
INTENT_SYSTEM_PROMPT      # BASE + 意图解析员角色锚点 + 意图清单 + JSON 格式 + 示例
CHAT_SYSTEM_PROMPT        # BASE + 校园对话助手角色锚点 + 文字禁代执行铁律 + 示例
PLAN_SYSTEM_PROMPT        # BASE + 学习规划师角色锚点 + 方案 JSON 结构 + 注入式示例
```

铁律只维护一份（BASE），改身份/边界只动一处，三条路径同时生效。

### BASE 层内容

- 身份：你是"智伴校园"平台的 AI 智能体助手，服务学生/教师/后勤；
- 铁律：
  1. 未经系统返回成功结果，绝不声称"已提交/已选课/已请假/已预约"；
  2. 写操作需要用户二次确认，只引导、不代替；
  3. 课程名、日期等以用户原话为准，不编造；
  4. 不确定、做不到时如实说明；
  5. 简洁中文。

### 三个任务层的角色锚点（各一行，写在任务层开头）

- 意图层：「你是一个意图解析员，只输出意图解析 JSON。」
- 聊天层：「你是一个校园对话助手，根据对话事实返回自然语言。」
- 方案层：「你是一个学习规划师，根据课表数据输出结构化方案 JSON。」

### 聊天层补充铁律（用户修订点 1）

> 禁止在用户完成确认前，以任何文字形式表示操作已执行（如"已提交/已选课/请等待审批"）。
> 写操作只能通过系统生成的确认卡片完成；你的职责是引导用户点击"确认执行"或回复"确认"，
> 并如实说明当前还没有执行成功的结果。

### 示例规范（用户修订点 3：注入数据后的真实形态）

示例一律呈现"线上真实调用形态"，即包含系统注入的数据：

- 意图层示例：`用户说"帮我选摄影课" → {"intents":[{"intent":"enroll","params":{"course":"摄影课"},"confidence":0.9}]}`
- 方案层示例：`用户指令"给明天学习方案" + 系统注入"明日课表：1. 高数 8:00-10:00 教一楼；2. 英语 14:00-16:00 教三楼" → {courses:[...]}`
- 聊天层反面示例：`用户问"提交成功了吗" → 若系统未返回成功，回答"还没有执行，需要你点击确认卡片完成提交"`

## 接入点

1. `app/services/agent/intent.py`：删除本地 `EXTRACT_SYSTEM_PROMPT`，改用 `INTENT_SYSTEM_PROMPT`；
2. `app/services/agent/actions.py::_handle_chat`：请求前注入 `CHAT_SYSTEM_PROMPT` 作为首条 system 消息（修复"无系统提示词"缺口）；
3. `app/services/agent/actions.py::_generate_plan`：临时提示词替换为 `PLAN_SYSTEM_PROMPT`。

代码层确定性逻辑全部保持不动：日期解析、课程模糊匹配、确认令牌、pending 续跑、规则兜底。

## 验证

- 新增 1 个用例：验证 `_handle_chat` 发出的首条消息是系统提示词，且包含"智伴校园"身份与文字禁代执行铁律；
- 现有 91 个测试保持全绿；
- 提示词总预算控制在约 600 token，不挤压 8000 token 上下文预算；
- 前端零改动。

## 非目标（YAGNI）

- 不把日期/课程解析搬进提示词；
- 不做外部文件加载或热更新；
- 不存数据库、不做后台编辑界面；
- 不改动规则引擎与确定性执行链路。

## 增补：智能体功能全量补齐（2026-08-03 追加）

在统一提示词落地的同时，按既有"意图参数抽取 → 预检 → 确认卡片 → 确认执行"模式补齐 4 个新意图：

| 意图 | 功能 | 适用角色 | 写操作 | 业务来源 |
|------|------|----------|--------|----------|
| `query_scores` | 查询我的成绩（含绩点） | student（教师可按学号查） | 否 | `GET /scores/student/{id}` |
| `query_notifications` | 查看通知列表 + 未读数 | 全部角色 | 否 | `GET /notification/list`、`GET /notification/unread-count` |
| `approve_leave` | 审批请假（通过/驳回） | teacher / admin | 是（确认卡片） | `POST /advisor/approve` → `leave_service.approve` |
| `query_exams` | 我的考试 / 监考安排 | student / teacher | 否 | `GET /exam/my-exams`、`GET /exam/my-invigilations` |

### 各意图要点

- **query_scores**：无参时查自己（role_id 即学号）；教师可带 `params.student`（学号）。返回课程/分数/绩点卡片。
- **query_notifications**：返回最近 5 条通知 + 未读数卡片。
- **approve_leave**：`params.leave`（请假编号或学生姓名/学号，从待审批列表解析）+ `params.result`（通过/驳回）+ `params.comment`（意见，可选）。预检：记录存在且处于待审批状态、当前角色可审批；确认后调 `leave_service.approve`。角色限制 teacher/admin，加入 `NOT_FOR_STUDENT` 集合。
- **query_exams**：按角色返回学生考试安排或教师监考安排。

### 配套改动

- `IntentType` 增加 4 个枚举；`INTENT_SYSTEM_PROMPT` 意图清单加入新意图及参数说明；
- 规则兜底：新增关键词（"成绩/绩点"、"通知/未读"、"审批/通过请假/驳回"、"考试/监考"）与参数抽取；
- 前端确认卡片信息行已通用渲染（`confirmInfo`），审批卡片复用无需改动；
- 测试：每个新意图补动作层 + API 层用例，总量预计 91 → 100+；
- README 指令表与功能状态同步更新。

### 验证

- 新增用例：成绩/通知/考试为只读卡片；审批走"预检 → 确认卡片 → 确认后状态流转"（含驳回路径）；
- 现有 91 个用例保持全绿；
- 前端零改动（确认卡片通用渲染已具备）。
